# Discovery

Write `docs/product/discovery.md`. Replace every `TODO(factory)` marker. Keep it under ~2 pages.

Required sections (exact headings): Problem, Target users, Value proposition, User journeys, Assumptions, Risks.

Method:
1. State the problem without naming a solution. Who hurts, how often, what it costs them today.
2. 1–3 target user profiles: context, goal, current workaround. No invented personas with fake quotes.
3. Value proposition: why this beats the current workaround, in one sentence plus 3 bullets.
4. 2–4 user journeys as numbered steps.
5. Assumptions table: assumption | evidence (or "none yet") | how to test cheaply. Market demand,
   competitor claims and user research are assumptions unless a reference in references/catalog.json supports them.
6. Risks: product, technical, legal/compliance. Flag features that do not serve the core problem.

Challenge weak assumptions explicitly. If the idea is vague, ask the user rather than inventing scope.
Also fill the "What it does" and "Who it is for" sections of docs/PRODUCT_BRIEF.md (short).
